## 1. 你的 RTSPHEM-main 里，溶质输运怎么求？

你的 `TransportLEVEL` 本质上是在 level-set 描述的流体区域内求一个混合形式的对流–扩散问题。类说明里写得很明确：它是用于 time-dependent domain 的 transport problem，level-set 会自动识别内部边界；所有 level-set 值满足特定条件的三角形会被视为固体，不属于流体域。

它求解的基本形式是：

[
\vec q=-\mathbf D\nabla u+\vec C u+\vec E
]

[
\partial_t(Au+B)+\nabla\cdot \vec q=F
]

也就是说，`TransportLEVEL` 的未知量包括通量 (q) 和浓度/标量 (u)，空间上更接近 **mixed FEM / RT0-P0** 的风格。源码注释里还说明了 Dirichlet、Neumann、flux 边界条件形式。

它内部确实已经意识到高 Pe 问题。`TransportLEVEL.m` 的说明中写了，当局部 Péclet 数很大时，需要稳定化以抑制 spurious oscillations，并提供 `none`、`full`、`exp`、`alt` 四种 upwind 策略。

在 `assembleSystem.m` 里，它会计算局部 Pe：

```matlab
Pe = tp_pecletnumbers(this, dataC, dataD);
```

然后根据 `this.isUpwind` 选择 upwind 权重，包括 `full`、`exp`、`alt`。

但是这里有两个很关键的问题。

第一，`full upwind` 不是严格意义上的 bounded finite volume scalar transport。它只是改变装配中对流项的权重，不等于保证：

[
0 \le c \le c_{\mathrm{inlet}}
]

第二，你的代码里确实存在一个很可疑的硬编码：

```matlab
if size(marknonneumE, 1) >= 500
    marknonneumE(500, 1:2) = 0;
end
```

这个代码在 `TransportLEVEL/assembleSystem.m` 里是真实存在的。
这个非常像调试残留，不应该保留在正式求解器里。它会强行修改第 500 个单元的边界/通量标记，在高 Pe 下可能被对流放大成局部异常。

## 2. GeoChemFoam 里，溶质输运怎么求？

GeoChemFoam 的 `reactiveTransportDBSFoam` 是 OpenFOAM 有限体积框架下的微连续介质 DBS 反应输运求解器。主程序说明写的是：它用于求解 **microcontinuum DBS for multi-species flow**。

它的主流程大概是：

1. 更新动态网格；
2. 解 `epsEqn.H`，更新流体体积分数/孔隙率；
3. 根据 (\epsilon) 更新渗透率；
4. 计算 (\nabla \epsilon)、界面法向和界面面积；
5. 在 steady-state loop 中解速度压力 SIMPLE；
6. 解 `YiEqn.H` 中的多组分浓度输运方程。

GeoChemFoam 的浓度输运方程在 `YiEqn.H` 里。核心矩阵是：

```cpp
fvScalarMatrix YiEqn
(
    fvm::div(phi, Yi, "div(phi,Yi)")
  + fvm::SuSp(-fvc::div(phi),Yi)
  - fvm::laplacian(D, Yi)
  + Ri
);
```

并且它在求解后做了：

```cpp
Yi = max(Yi,0*Yi);
```

也就是至少强制去掉负浓度。

这个点对你很重要：GeoChemFoam 不只是求“对流–扩散”，它用的是 OpenFOAM 的 **finite volume conservative flux form**。`fvm::div(phi,Yi)` 是通量形式的对流项，`fvm::laplacian(D,Yi)` 是扩散项，`Ri` 是反应项。

另外，GeoChemFoam 的反应项处理分两类：

传统 `VoS-psi`：

```cpp
Ri += scoeffj[i]*a*Rj;
```

iVoS：

```cpp
Ri += fvc::div(phiREps)-eps*fvc::div(phiR);
```

也就是说，VoS-ψ 是把界面反应写成局部体积源项，而 iVoS 用反应通量散度来构造反应项。

## 3. 两者在溶质扩散运移上的共同点

它们的物理目标是一样的，都是在模拟反应物在孔隙结构中的：

[
\text{advection} + \text{diffusion} + \text{reaction}
]

共同点有三个。

第一，二者都把速度场 (u) 作为已知或当前迭代得到的流场，然后用它驱动 H⁺/反应物输运。

第二，二者都有扩散项。你的 RTSPHEM 通过 (\mathbf D) 进入通量：

[
q=-D\nabla c + Cc
]

GeoChemFoam 通过：

[
-\nabla\cdot(D\nabla c)
]

对应到源码里的：

```cpp
- fvm::laplacian(D, Yi)
```

第三，二者都把反应项与界面有关。你的模型是 level-set sharp interface，界面处有：

[
-D\nabla c\cdot n=R(c)
]

然后界面按 (v_n=V_mR(c)) 后退。GeoChemFoam 的 VoS/iVoS 则是在体积分数场 (\epsilon) 的弥散界面附近构造体积反应项。你的论文 Supporting Information 里也明确写了 level-set RTM：Stokes flow、H⁺ advection–diffusion、一阶表面反应和 level-set 界面推进。

## 4. 两者最大的数值差异

核心区别不是“谁求不求对流扩散”，而是**对流扩散方程的离散和界面反应放置方式不同**。

| 对比项   | 你的 RTSPHEM-main                      | GeoChemFoam                                                  |
| ----- | ------------------------------------ | ------------------------------------------------------------ |
| 几何表示  | level-set，(\phi_{ls}=0) 是清晰界面        | VoS/micro-continuum，(\epsilon) 表示体积分数                        |
| 计算域   | 主要在 level-set 定义的孔隙域内求解              | 整个域求解，固体区通过小孔隙率/大阻力弱化                                        |
| 输运离散  | `TransportLEVEL`，mixed FEM/RT0-P0 风格 | OpenFOAM finite volume                                       |
| 对流项   | `C` 矩阵装配 + upwind 权重                 | `fvm::div(phi,Yi)` 通量形式                                      |
| 扩散项   | (\mathbf D) 进入局部矩阵 `HlocT`           | `fvm::laplacian(D,Yi)`                                       |
| 反应项   | 界面通量边界条件，然后推进 level-set              | 体积源项 `Ri`，VoS-ψ 或 iVoS                                       |
| 有界性保护 | 目前主要靠 upwind，缺少严格 clamp/reject       | 至少有 `Yi=max(Yi,0)` 的非负截断                                     |
| 时间步保护 | 你主要有 reaction/level-set CFL          | GeoChemFoam 有 `CourantNo`、`deltaEpsMax`、`setDeltaT` 等时间步控制流程 |

GeoChemFoam 在主程序中每步都会计算 `CourantNo` 和 `deltaEpsMax`，然后通过 `setDeltaT.H` 调整时间步。
它的 `epsEqn.H` 里还会更新流体体积分数，并强制：

```cpp
eps = min(max(0.0,eps),1.0);
```

也就是把 (\epsilon) 限制在 ([0,1])。

这个思想对你很值得借鉴：**不要让一个物理量越界后继续污染后续步骤。**

## 5. 你的高流速失稳，能不能借鉴 GeoChemFoam 修？

能，而且我建议分成 **短期修复、中期增强、长期重构** 三层。

### 短期：先修明显 bug 和加保护

第一步，直接删掉 `TransportLEVEL/assembleSystem.m` 里的这段：

```matlab
if size(marknonneumE, 1) >= 500
    marknonneumE(500, 1:2) = 0;
end
```

这个不应该存在。它会破坏某个单元局部边界/通量标记。高 Pe 下局部异常很容易被对流输运放大。

第二步，在 transport 求解后、reaction/level-set 更新前，加浓度范围检查：

```matlab
cMin = min(c(:));
cMax = max(c(:));

badConcentration = ...
    cMin < -1e-12 || ...
    cMax > 1.05 * cInlet;

if badConcentration
    % reject step, reduce dt, recompute transport
end
```

GeoChemFoam 至少对负浓度做了 `Yi=max(Yi,0)`。
但对你这里，**我不建议只做简单 clamp**。因为你的 H⁺ 浓度直接控制反应速率，正向 overshoot 会导致反应速率假增大。更好的做法是：

**轻微负值可以截断；明显正向超入口浓度，要拒绝该步并减小时间步或增强稳定化。**

---

### 中期：引入 Pe-based 局部人工扩散

你 md 里已经判断得很对：关键不是单独 advective CFL，而是：

[
Pe_{\mathrm{local}}=\frac{uh}{D}
]

当前实验显示 (Pe_{\mathrm{local}}\approx4\sim5) 稳定，而 20–40 容易失稳。

因此可以借鉴 GeoChemFoam “用数值耗散稳定对流项”的思路，但在你的 Matlab/HyPHM 框架里实现成局部有效扩散：

[
D_{\mathrm{eff}}=D+D_{\mathrm{art}}
]

[
D_{\mathrm{art}}=\max\left(0,\frac{|u|h}{Pe_{\mathrm{target}}}-D\right)
]

建议先取：

[
Pe_{\mathrm{target}}=8
]

如果仍然 overshoot，再降到 5。

这不是物理扩散系数全局增大，而是**只在高 Pe 局部区域增加数值稳定化**。这样比把 (D) 全局放大 10 倍合理得多。

实现位置上，你可以在进入 `TransportLEVEL` 的 `dataD` 之前，构造每个三角形的 `D_eff`，替代原来的常数扩散张量。也就是说，先不动底层矩阵装配，只改变传入的 `dataD`：

```matlab
uMagT = sqrt(uTx.^2 + uTy.^2);   % 每个三角形速度尺度
hT    = grid.hT;                 % 或者用 sqrt(areaT)
Dphys = cfg.D_H;

PeTarget = 8;
Dart = max(0, uMagT .* hT ./ PeTarget - Dphys);
Deff = Dphys + Dart;

dataD(:,1) = Deff;
dataD(:,4) = Deff;
dataD(:,2) = 0;
dataD(:,3) = 0;
```

这个方案本质上是在高 Pe 前锋附近增加“有限体积 upwind 类似的数值耗散”，但保留你现有 `TransportLEVEL` 架构。

### 中长期：新增 bounded FV transport solver

如果你想从根上解决，最好新增一个 **bounded finite-volume scalar transport solver**，先只替换 H⁺ 输运，不动 Stokes 和 level-set。

GeoChemFoam 最值得你借鉴的就是这里：它把浓度输运写成有限体积守恒通量形式：

```cpp
fvm::div(phi, Yi, "div(phi,Yi)")
- fvm::laplacian(D, Yi)
+ Ri
```

并且输运方程是在每个控制体上做通量守恒。

你的版本可以先做一个最稳的版本：

[
\frac{A_K(c_K^{n+1}-c_K^n)}{\Delta t}
+
\sum_{e\in\partial K} F_e c_{\mathrm{upwind},e}^{n+1}
-----------------------------------------------------

# \sum_{e\in\partial K} D_e\frac{c_N^{n+1}-c_K^{n+1}}{d_{KN}} |e|

S_K
]

然后对每条边用 upwind：

[
c_{\mathrm{upwind},e}=
\begin{cases}
c_K, & F_e>0 \
c_N, & F_e<0
\end{cases}
]

这个版本会比现在的一阶精度更耗散，但非常适合先把高流速跑稳。等稳定后，再考虑 TVD/minmod/vanLeer limiter。

## 6. 不建议直接照搬 GeoChemFoam 的 iVoS

这个点要小心。

你的代码是 **level-set sharp-interface**；GeoChemFoam 的 iVoS 是 **VoS diffuse-interface**。iVoS 中的这类反应项：

```cpp
Ri += fvc::div(phiREps)-eps*fvc::div(phiR);
```

是基于 (\epsilon) 体积分数、(\nabla \epsilon)、界面法向和微连续介质假设构造的。

你没有 (\epsilon) 作为主几何变量，而是有 (\phi_{ls})。所以不建议把 iVoS 的反应项直接搬进你的 level-set 框架。

你应该借鉴的是这些“数值工程思想”：

1. 浓度方程用守恒通量形式；
2. 高 Pe 对流项用 bounded / upwind / limiter；
3. 浓度求解后做范围诊断；
4. 非物理值不要进入 reaction；
5. 几何变量更新后强制保持合法范围；
6. 时间步由 advective CFL、reaction CFL、界面移动量和浓度有界性共同控制。
